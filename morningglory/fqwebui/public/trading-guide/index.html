02 · Web 可视化系统运行逻辑 当前线上

前端怎么把账本画到屏幕上

技术栈：Vue3 + Element Plus；请求统一走 src/api/*.js → @/http（axios）；刷新统一用 @tanstack/vue-query 的轮询策略（pollingNormal）。

① 持仓列表 StockPositionList.vue

挂载即发起 useQuery(['stockPositionList']) + pollingNormal → GET /api/get_stock_position_list?page=1&size=1000；一次拉全量（当前数据源 = XT 持仓快照），前端 lodash 切片分页；翻页/改页大小 → invalidateQueries 重拉；点品种 → 新窗口开 /kline-big?symbol=&period=1m。

② 复盘工作台 PositionReview.vue

Workbench 布局（Toolbar / SummaryRow / Panel / Sidebar / Ledger / Detail / StatusChip）；接口族 /api/position-review/**：summary、symbols、symbols/{symbol}、symbols/{symbol}/chart、events/{id}/conditions、portfolio/summary|series|contributions；打开流程 = 总览 → 标的列表 → 选中标的明细 + 走势。

③ K线大图 /kline-big

数据来自 /api/stock_data?period=&symbol=（K线），可叠加 CLX 模型 / 信号标注；持仓列表与复盘页均可跳转进入。

轮询周期由 queryPolicies 控制；前端只读、不写交易状态。

运行逻辑一句话：Worker 写库 → rear 读库出 API → 前端轮询渲染。前端不做交易决策、不直接写交易状态，看到的永远是账本的最新投影。

03 · 一图看懂 · 一句话模型 当前线上

一图看懂：整个体系的「一句话模型」

把复杂系统压缩成一条主线：选股 → 确认 → 开仓 → 管理 → 退出。每一步都有独立的周期和职责。

1

选股

每天收盘后，用 18 个缠论模型（CLX）在全市场「海选」出值得跟踪的股票，进入候选池。

日线级别 · 不交易
2

盘中确认

第二天盘中，15 分钟 / 30 分钟级别的 CLX 模型持续「复查」，确认候选股没有走坏。

15/30 分钟 · 只看不买
3

首次开仓

当 5 分钟级别出现「V 反」或「MACD 看涨背驰」信号时，系统才第一次买入。

5 分钟 · 首次买入
4

持仓管理（做T）

持有期间切到 1 分钟级别：跌出空间就补仓摊低成本，反弹达标就卖出部分，循环降低持仓成本。

1 分钟 · 加仓/减仓
5

止盈止损

全程用 Tick（逐笔）行情盯住：到三档止盈价就分批兑现；跌破止损价就果断离场。

Tick 级别 · 计划退出
新手最容易误解的一点： 三个补仓价（B1/B2/B3）不是「止损」。它是下跌时的补仓计划； 真正的风险底线由全仓止损价和单笔止损价负责。

每天收盘后（15:05 之后），系统用冻结的 production_v1 参数运行 18 个缠论模型（S0000–S0017），在全部 A 股与 ETF 中寻找形态符合条件的标的，结果进入「候选池」。这一层解决的是「买什么」，它不看盘中价格，所以不可能在这里下单。

仓位与风控允许

账户状态允许开新仓、单标的不超仓位上限、两次新开仓之间至少间隔 15 分钟。

为什么用 5 分钟而不是 15/30 分钟直接买？ 15/30 分钟负责「方向对不对」，但节奏太慢；1 分钟太敏感、噪音大。 5 分钟是「确认方向后，等一个更精确的入场点」的折中周期。

底仓与做T：两本并行账本 + 金字塔补仓

把「首次开仓 + 3 条抄底线补仓」和「中间做T」拆成两本独立账本： 底仓（靛蓝）由 3 条抄底线买入（只买扣减做T后的剩余）、3 条止盈线卖出（1/3 → 1/2 → 全部）； 做T（琥珀）在四段走廊按金字塔曲线补仓、按统一盈利谓词逐档卖出。 两套策略并行叠加，总仓 = 底仓 + 做T。

底仓账本（base）

首次开仓
  • 谁进来：首次开仓（must_pool 首开 / 手动首开）+ 3 条抄底线补仓（固定价格触发，计入底仓）
  • 买入：价格触及 BUY-1/2/3 → 买入 cap_N − 占用 − 在途（只买扣减做T后的剩余）；触发即关该线及以上
  • 卖出：只走三档止盈线，按底仓总量卖 1/3 → 1/2 → 全部，3 次触发清空；触发即关该档、成交后关该档及以下并全开抄底线、零成交重开

做T账本（t / Garden）

1 分钟加仓
  • 谁进来：Guardian 信号加仓全部归做T（T 买入不触发状态机）
  • 买入：先过下跌阈值（threshold），再按四段走廊金字塔数量：回补走廊 [最近止盈线, BUY-1]/cap1、[BUY-1,BUY-2]/cap2、[BUY-2,BUY-3]/cap3、破线区 global_cap（1/2 收敛）
  • 卖出：统一盈利谓词 signal ≥ guardian_price × (1 + percent/100) + mount（默认 5 万）；手动/外部卖单分摊 = ① T 盈利低成本 → ② 底仓 → ③ T 非盈利兜底

买入金额 B = R × t^n

下限与整手 B ≥ min_buy_amount(1万) 且 Q ≥ 100 股

Q = floor(B / p / 100) × 100；不足则不买，不消耗冷却

07 · 三档止盈 当前线上

止盈不是「一次卖光」，而是三档分批兑现

系统为每只股票设定 L1 / L2 / L3 三个固定价位，价格每上一档，就卖掉「当时总仓位」的一部分。

L1
10.20
卖出 1/3

第一档：涨到这里，先落袋一部分，锁定利润，也留足子弹。

L2
11.05
卖出剩余 1/2

第二档：继续上涨，再卖一半。注意：是按触发时的剩余仓位算，不是按最初仓位。

L3
12.00
全部卖出

第三档：价格到顶位，清仓离场，完成一次完整周期。

档位卖出比例动画

未触发：持有 100%

L1 卖 1/3 → L2 卖剩余 1/2 → L3 卖全部。档位触发后，低于该档的档位会一起关闭，不会重复触发。

小知识： 止盈卖出并不是「随便挑一些股票卖」，而是优先卖已经盈利的买入切片；盈利切片不够时，再从剩余数量最大的切片补足。每一笔买入都会被打上「切片」标签，方便精确核算。

08 · 止损防线 当前线上

补仓不是「无限接飞刀」：两层止损守住底线

很多新手以为系统只补仓不止损，其实它有两条明确的纪律线，专门防止「越跌越买、越买越亏」。

全仓止损

整个股票一起止损

  • 价格来源：must_pool 里人工设置的全仓止损价
  • 触发条件：买一价 ≤ 全仓止损价
  • 动作：卖出该股票全部可卖持仓
单笔止损

每一笔买入单独止损

  • 价格来源：每一笔买入（entry）可以绑定自己的止损价
  • 触发条件：买一价 ≤ 该笔止损价
  • 动作：只清掉这一笔，其他持仓保留

价格防线一览（把上面两层放在价格轴上）

B3 补仓 9.55 B2 补仓 9.25 B1 补仓 8.95 全仓止损 8.60 L1 止盈 10.20

左边是「越跌越买」的补仓带（橙色），右边是「跌过头就清仓」的止损线（红色）与止盈线（紫色）。补仓带和止损线之间，就是系统允许价格波动的「缓冲区间」。

09 · 风险护栏 当前线上

除了价格，系统还有 4 道「看不见的护栏」

这些护栏不产生买卖信号，但任何一笔单子都必须通过它们，否则会被拦下。

🛡

单标的仓位上限

每个股票最多占用多少资金，超出上限就拒绝继续买入。系统默认上限可全局设置，也可单独覆盖某只股票。

🚦

账户状态门禁

账户处于「允许开仓」状态才能买新股票；处于「仅可加仓」状态只允许补仓；处于「强制减仓」状态则禁止一切买入。

⏱

冷却时间

同一股票买卖后 15 分钟内不再重复操作；两次「新开仓」之间也至少间隔 15 分钟，防止信号噪音引发频繁交易。

📋

订单账本与对账

每一笔委托、成交、持仓都会被记录成「账本」，与券商数据持续对账。账目对不上时，系统宁可暂停也不乱下新单。
